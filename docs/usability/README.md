# 可用性测试工具包

用 [三张任务卡](../../lofi-prototype/task-cards.html) 测试交付版页面。目标是回答三个问题：

1. 第一次使用的人能不能**不靠提示**完成 T1–T3？
2. 完成后，他们说出的结论**和页面数据一致**吗？（不是"点到了"，而是"读对了"）
3. 卡住的地方在哪里，为什么卡住？

结果按 [issues/README.md](../../issues/README.md) 的格式记成 issue，每个问题一个文件，证据写清是哪位参与者、哪一步、说了什么。

## 参与者（3–5 人）

| 角色 | 人数 | 筛选条件 |
|---|---|---|
| 开发者 | 2 | 做过或正在做独立游戏；不需要懂统计 |
| 玩家 | 2–3 | 过去一个月在 Steam 上玩过游戏；至少一位用手机或只用键盘 |

没参与过本项目的人。每人约 30 分钟。开发者做 T1 → T2，玩家做 T3；时间够时，玩家也可以做 T1，看非专业用户能否读懂"拥挤"。

## 准备

- 交付包：`steam_tag_dashboard.html` 和同级的 `covers/` 文件夹。**断网**打开，确认封面能显示。
- 浏览器：Chrome 或 Edge 最新版，窗口 1280×800 以上；手机参与者用自己的手机（360–430 px 宽）。
- 每位参与者开始前清空地址栏里的 `#…`，从开场页开始。
- 录屏和录音（征得同意）。主持人和记录员各一人；只有一个人时，记录员的工作看录像补。
- 打印 [记录表](记录表.csv) 一人一份。

## 主持人脚本

### 开场（2 分钟）

> 谢谢你来。我们在测试这个网页，不是在测试你，任何卡住的地方都是网页的问题。
> 做任务时请**边做边说**：你在看什么、在找什么、觉得这是什么意思。
> 我大多数时候不会回答问题，因为想看看网页自己能不能讲清楚。你随时可以停下。

### 任务

每个任务**只念任务卡上的原话**，然后把卡片放在参与者面前。不要说"Studio""赛道""拥挤度"这些页面里的词。

| 任务 | 起点 | 念给参与者 |
|---|---|---|
| T1 | 开场页 | 你想做一款卡牌游戏。找一个比平均做得好的标签组合。这个方向是不是越来越挤了？ |
| T2 | 接着 T1；如果 T1 没走到 Studio，主持人帮忙打开 `#studio/plan/Deckbuilding+Rogue-lite/r` 并记一次"协助" | 你在做一款 Deckbuilding + Rogue-lite 游戏。比较方案 A 和方案 B。你会选哪个？想改什么？ |
| T3 | 开场页（新打开） | 输入三款你玩过的游戏。选出比较时你在意什么。拿到推荐，挑一款，告诉我们它为什么被推荐。 |

### 什么时候介入

- 参与者沉默超过 20 秒：问"你现在在想什么？"
- 同一处卡住超过 2 分钟，或者参与者说要放弃：给**最小提示**（例如"页面上还有别的入口吗？"），在记录表记一次"协助"并写下提示内容。
- 参与者问"这个对吗？"：反问"你觉得呢？为什么？"

### 每个任务结束后

1. 请参与者**用一句话说出结论**，原话记下。
2. 追问依据："你是从页面哪里看出来的？"请他指给你看。
3. 难度打分（SEQ）："整体来说，这个任务有多难？1 = 非常难，7 = 非常容易。"

### 收尾（5 分钟）

- 哪一步最让你困惑？
- 有没有哪个数字你不信，或者看不懂？
- 如果明天还要做这件事，你会再用这个页面吗？为什么？

## 判断"完成"和"读对"

完成 = 参与者自己走到能回答问题的页面。读对 = 他的结论和下面的参考答案方向一致，并能指出依据。下面的数字来自 2026-11-18 的数据和"评价 ≥ 500"标准；数据或口径更新后，测试前先在页面上核对一遍。

| 任务 | 完成的标志 | 读对的标志（参考答案） |
|---|---|---|
| T1 | 打开了卡牌赛道的分析（Studio「选赛道」，Card Game） | 说出 Card Game 本身高于大盘（约 1.3 倍）；指出至少一个让表现更好的搭配标签（如 Deckbuilding、Turn-Based、Roguelike Deckbuilder），并说明依据是倍数或区间；对"是否变挤"给出带依据的回答：加上 Deckbuilding 后新作份额明显上升（约 0.3% → 2%），优势在缩小 |
| T2 | 在「比较方案」里同时看到 A 和 B 的估计 | 选 A，理由提到 A 的成功机会更高且差值的区间不跨 0（约 +9 个百分点）；提出的修改有页面依据（例如支持更多语言），并知道这是相关关系 |
| T3 | 输入了 3 款游戏并拿到推荐 | 挑一款后，说出的理由和页面理由面板一致（例如共同标签、和哪款最接近、价格或好评差多少），没有编造页面没给的理由 |

## 要记的指标

- 是否完成、协助次数、用时（从念完任务到说出结论）。
- 是否读对；说错时记下错在哪里（看错数字、把相关当因果、误解了"拥挤"等）。
- SEQ 分数。
- 每次犹豫、走错页面、来回切换的位置。

## 整理成 issue

1. 每个问题一个文件，用下一个流水号，类型通常是 `ux`。
2. 证据写"P2 在 T1 第 3 步，在星图上找了 1 分 40 秒入口，说'我不知道从哪里开始'"这样的原话和位置。
3. 优先级：导致任务失败或结论读错的记 P1；拖慢但能完成的记 P2；只是抱怨的记 P3。
4. 同一个问题出现在 2 位及以上参与者身上时，在标题里注明。
